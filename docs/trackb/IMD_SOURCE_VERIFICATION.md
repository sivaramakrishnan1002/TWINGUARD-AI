# B38 — IMD rainfall and weather source readiness

**Verified:** 2026-11-05  
**Disposition:** **PROPOSED / NOT AUTHORIZED for integration.** The official documentation identifies candidate products and endpoint shapes, but this review did not verify entitlement, unauthenticated access, a Chennai API selector for most products, or operational freshness. No connector was implemented.

## Scope and method

This review used the B34 repository inventory and the official IMD materials listed below. It inspected published documentation and public navigation only. It did **not** request any product/data API URL, including an unauthenticated GET or HEAD. The API portal links registration/login, and IMD's API notice says interested organizations must follow IMD terms and contact its nodal officer; the reviewed materials do not publish the applicable terms or API rate limits. B38's prerequisite therefore does not permit probing. There is no actual product response, sample hash, or observed API update interval in this report.

`https://api.imd.gov.in/public/` exposes **Register**, **Create Account**, **Login**, and **Explore APIs**. This indicates an account workflow exists, but does not establish per-endpoint authentication requirements or rule out anonymous access. Authentication/registration for each product remains **UNKNOWN**. Do not treat the words “real time” in the portal description, “Current Weather,” or a published forecast/nowcast as evidence that this project has live entitlement or an SLA.

## Cadence: documentation versus observation

IMD's [forecasting SOP](https://mausam.imd.gov.in/imd_latest/contents/pdf/forecasting_sop.pdf) documents station and district nowcasts at **three-hour intervals**. The [IMD Annual Report 2022](https://mausam.imd.gov.in/imd_latest/contents/ar2022.pdf) also describes district nowcasts for all districts round-the-clock at three-hour intervals, updated every three hours on the IMD website. This is the **documented product issue/update cadence** for those nowcasts. It is not measured API freshness, delivery latency, an endpoint SLA, or proof that a given row is refreshed on schedule.

For all products, **observed API update cadence is UNKNOWN**: this task performed zero data endpoint observations. For city forecast, current weather, rainfall statistics, AWS/ARG, basin QPF, subdivision forecast, and district rainfall forecast, the reviewed published API reference does not specify an update schedule. None should inherit the nowcast cadence.

## Access, legal terms, provenance, and operational gaps

- **Owner:** IMD, Ministry of Earth Sciences, publishes the APIs. Product-level custodian, API account owner, and project contact remain to be agreed.
- **Access:** Portal offers account creation and login. Whether each product requires registration/authentication, and whether anonymous access is allowed, are **UNKNOWN**. No account was created and no credentials were used.
- **Permission/terms:** IMD's [API notice](https://mausam.imd.gov.in/Forecast/marquee_data/API_doc.pdf) says organizations interested in using APIs must follow IMD terms and contact its nodal officer. The reviewed notice does not enumerate those terms. License, permitted purpose, fees, retention, redistribution, attribution, and rate limits are **UNKNOWN**. This report is not a legal permission grant.
- **Data provenance:** API docs give product descriptions and examples, not a retrieved response. Source instrument/model, per-record provenance, QC, sample hashes, and revision/backfill behavior are generally **UNKNOWN**. Product-specific documented code/category fields are listed above. NoData must not become zero; for rainfall statistics `ND` differs from `NR`.
- **Spatial support:** Products range from station/city points to district, subdivision, state, or basin summaries. Chennai display/navigation is evidence of a regional product, not proof of exact API coverage, selector, or resolution. AWS state ID 25 is documented as Tamil Nadu, but its Chennai station roster is unknown.
- **Latency/failure:** Publication timestamps, actual delay, freshness bounds, timeout/retry guidance, HTTP error meanings, null/missing representation, outage behavior, and correction policy are **UNKNOWN** except where explicitly stated in the source descriptions. No endpoint error behavior was tested.
- **Source mode:** Candidate API products are **PROPOSED**, not verified LIVE. This review did not obtain new REPLAY data. Forecast, nowcast, current observation, and accumulated rainfall statistics are distinct product semantics and must not be collapsed into a single “live rainfall” feed.

## Required human follow-up before any access or integration

1. Obtain written IMD approval and the applicable terms, with project purpose, allowed endpoints, registration/auth requirements, rate limits, fees, storage/retention, redistribution, and attribution.
2. Ask IMD/RMC Chennai for exact city, station, district, subdivision, state and basin selectors relevant to Chennai, with authoritative mapping evidence and spatial boundary/vintage.
3. Obtain authorized schemas/sample payloads with types, units, rainfall accumulation windows, source/valid/publish timestamps and timezone, QC, NoData/null codes, and error semantics. Hash any lawfully supplied sample without placing credentials in the repository.
4. Obtain the product publication schedule and revision/backfill policy. After permission only, measure actual publication/update latency over a stated observation window and record request/response timestamps and method.
5. Keep all candidates proposed until those decisions are recorded. Do not implement a connector or assert live access from documentation alone.
